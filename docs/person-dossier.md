# Всё найденное о человеке — в его карточке

Досье связывает описание жизни и деятельности, фотографии, документы, ссылки и исследовательские находки с конкретным человеком. Тексты и список материалов хранятся в `case.json`, оригинальные файлы — в частном семейном деле. Утверждения с источниками остаются в `evidence.json` и показываются рядом.

## Открыть своё дело для работы

Из папки репозитория:

```bash
node bin/drevo.mjs dossier ../my-family-case --port 4174
```

Откройте напечатанный локальный адрес, найдите человека и откройте его карточку. Сервер работает на этом компьютере. Семейное дело должно находиться вне публичного репозитория и уже содержать людей с устойчивыми ID.

В локальной карточке можно:

- вести описание жизни и отдельно — деятельности: учёба, места работы, занятия, должности и периоды;
- прикреплять фотографии, сканы, PDF, расшифровки, записи голоса и другие разрешённые файлы;
- добавлять внешние ссылки, названия, даты, описания, сведения об источнике и архивный шифр;
- просматривать материалы и открывать оригинал, не разыскивая его по папкам;
- читать все связанные с человеком утверждения, включая версии и противоречия, через раздел находок.

Сохранение описания записывает его в дело. Предыдущий `case.json` сохраняется в `working/dossier-history/`; эта история тоже частная. Копируйте для резервного хранения всё дело вместе с оригиналами. Если дело изменилось в другом окне или редакторе, приложение предложит обновить данные вместо незаметной перезаписи. Публичное демо и обычная статическая сборка доступны для просмотра; редактирование работает через локальную команду `dossier`.

## Файлы и их описание

На один файл действует ограничение **20 МиБ**. Файл копируется в `originals/dossier/` с собственным идентификатором. Приложение сохраняет исходные байты, размер и контрольную сумму; изменение подписи не изменяет оригинал. При удалении материала из карточки оригинальный файл остаётся в семейном деле.

Изображения, поддерживаемые браузером, можно рассмотреть; для документов доступен просмотр или открытие файла. Аудио и видео воспроизводятся только по действию пользователя. Форматы, которые браузер не показывает, предназначены для скачивания. Исполняемые файлы, HTML и SVG не принимаются как вложения. Внешняя ссылка не скачивает и не встраивает чужую страницу автоматически.

У каждого материала полезно указать:

| Поле | Что записать |
|---|---|
| Название | Что это: фотография, выписка, личное дело, письмо |
| Описание | Что видно, кто предположительно изображён, что ещё нужно проверить |
| Дата | Дата материала, если известна; не подменять её датой загрузки |
| Источник | Архив, владелец снимка, сайт или человек, передавший материал |
| Ссылка | Устойчивая страница записи или коллекции |
| Локатор | Фонд, опись, дело, лист, номер записи или кадра |
| Права | Авторство, условия использования и основание для публикации |

Сохраняйте оригинальный скан и расшифровку отдельными материалами. В описании расшифровки укажите, создана ли она вручную или через OCR, и что сверено по изображению. Не выдавайте предположительное чтение за точную цитату.

Прикреплённый документ сам по себе не создаёт новую родственную связь и не повышает статус утверждения. Чтобы объяснить, что именно он подтверждает, оформите источник и утверждение в `evidence.json`. [Правила работы с основаниями](professional-practice.md).

## Выбрать портрет для карточки и дерева

Чтобы показать конкретную фотографию в заголовке карточки и на листе дерева, укажите её ID в `people[].dossier.portraitMaterialId`:

```json
{
  "portraitMaterialId": "portrait-example",
  "materials": [
    { "id": "portrait-example", "title": "Подписанный портрет", "file": { "...": "обычные поля уже прикреплённого изображения" } }
  ]
}
```

Это сокращённый пример выбора, а не готовый файл дела. Материал должен принадлежать этому человеку и содержать локальное изображение поддерживаемого формата. Внешняя ссылка или PDF портретом не становятся. Автоматического выбора по первому снимку или распознавания лица нет: атрибуцию проверяет исследователь. `null` снимает выбор.

Выбор пока задаётся в `case.json` агентом или вручную. Обычное редактирование биографии и подписи его сохраняет; удаление выбранного материала из карточки снимает портрет, сохраняя оригинал. Предпросмотр, локальное открытие и сборка проверяют наличие и байты выбранного изображения. Файл проходит существующий путь вложений `originals/` → `assets/materials/`, без отдельной копии в папке портретов.

Для публичной версии выбранное изображение должно пройти обычные разрешения материала, его файла и связанного источника. Разрешение описания без разрешения самого файла оставит публичную карточку без портрета. ID скрытого материала также не переносится в публичное досье.

## Находки человека

В карточке видны связанные с человеком утверждения с их собственными статусами, прочтениями, объяснениями и противоречиями. Это позволяет хранить вместе как подтверждённые сведения, так и ещё не проверенные версии. Совпадение фамилии или фотография соседней могилы остаются поводом для проверки.

Список находок шире линий дерева: утверждение может относиться к работе, учёбе, адресу или отдельному событию и не создавать родственной связи. Пометка `tree.include` управляет построением дерева, а не самим существованием исследовательской записи.

## Частное и публичное

Новое описание и загруженные файлы по умолчанию частные. Изменение ранее разрешённого биографического текста или подписи возвращает их в частный режим до нового выбора для публикации. Разрешение самих неизменённых байтов файла сохраняется, но без разрешённого описания материал в публичную версию не попадёт. Разрешения на публикацию разделены:

- `people[].tree.visibility: "public"` разрешает включить человека в публичную версию;
- `people[].dossier.visibility: "public"` разрешает описание жизни и деятельности;
- `materials[].visibility: "public"` разрешает описание конкретного материала;
- `materials[].fileVisibility: "public"` вместе с заполненным `rights` разрешает включить сам файл.

Это поля частного `case.json`, которые агент или пользователь выставляет после выбора состава публикации. Публичные находки также проходят проверку разрешений утверждений и источников. [Общие правила публичной проекции](case-to-tree.md).

Для подготовки версии выполните `tree-preview --public`, проверьте изменения и примените их через `tree-apply`. Каждая применённая версия viewer содержит свои копии отобранных файлов, чтобы откат сохранял прежнее содержимое. Публикуется только `viewer/dist/` выбранной версии. Ни частное дело, ни `originals/`, ни история изменений целиком для размещения не предназначены. Открытый просмотр чужого документа не означает право его перепубликовать.

## Воспроизводимый пример

В демо откройте **Глеба Листова**. В его досье есть описание вымышленных занятий, авторская иллюстрация рабочего стола, одностраничная PDF-карточка, текстовая расшифровка и пример внешней ссылки. В находках сохранено учебное расхождение года начала мастерской.

Иллюстрация не является исторической фотографией. PDF не является найденным архивным документом. Все люди, биографические сведения, шифры и ссылки этого примера вымышлены; домен `example.invalid` намеренно не существует. Учебные материалы созданы авторами Древа и распространяются по лицензии MIT проекта.
